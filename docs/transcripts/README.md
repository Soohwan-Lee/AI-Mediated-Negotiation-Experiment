# Simulated transcripts

Generated by `npm run simulate` against the real routes and the pinned model
(`gpt-5.6-terra`), not written by hand. They are committed because the checks
in `simulation-report.json` answer "did the assertions pass" and these answer
"does it read like a negotiation", which is the part no assertion covers.

Each speaker is labelled the way the interface labels them — **Your AI Proxy**,
**Their AI Proxy**, **Other Participant** — so a transcript reads the way the
screen does. The counterpart is never given a name.

## What to look for

| File | What it demonstrates |
|---|---|
| `delegate-proxy.md` | The plain Delegate exchange: one work reason, ten messages, agreement. |
| `delegate-proxy-wr-and-sb.md` | **The ver.2.6 fix.** Work reason at stage 2, sensitive card at stage 4 — under the old per-issue cap the sensitive one was never voiced at all. Note it arrives depersonalised: the subject shifts off the speaker, the fault becomes a future risk, and it is anchored to the shared outcome. |
| `explorer-proxy-wr-and-sb.md` | The same mandate under Explorer. Stage 2 carries the principal's card **plus** an added pool clause in the same message, unlabelled and in the same voice — compare it against the Delegate's stage 2, which has only the card. |
| `explorer-proxy-sb-only.md` | The sensitive card with no work reason to fall back on, so the reframing rule is exercised on its own. |
| `direct-after-delegate.md`, `direct-after-explorer.md` | **The handover.** A Proxy task is not decided by the proxies — the participant takes over and finishes the negotiation, and what the two people agree is the result. Check the header line: the counterpart must resume mid-script rather than re-opening or re-challenging, because it did both through its own proxy. |
| `direct-after-proxy-no-reason.md`, `direct-after-proxy-with-reason.md` | The same handover from a weaker proxy position, with and without a reason having been voiced for the requirement. Not a controlled test of the reason rule — a live agent asked for a reason usually gives one, so the "no reason" run typically ends with one voiced. It shows that `request_reason` reaches a participant as an answerable question and that answering it changes the outcome. The deterministic contrast is in `tests/reason-rules.test.mjs`. |
| `baseline-direct.md` | A second model agent playing a participant against the real counterpart route. |

These are IDEAL trajectories — the logroll lands, both requirements hold, the
counterpart accepts at stage 4. They are for reading the flow, not for
exercising the failure branches.

## The annotated visualisation

`viz/reason-to-speech-en.html` and `viz/reason-to-speech-ko.html` take one
Explorer run and mark it up: which clause of the proxy's utterance came from
the participant's work reason, which from their sensitive background, and
which the AI added from the pool — with the original card text and the
transformation shown beneath each one. Rebuild with:

    python3 scripts/build-transcript-viz.py

Both languages are generated from one structure in that script, so the
argument cannot drift between them. The colour coding exists ONLY in this
document: on a participant's screen nothing distinguishes a pool argument
from the participant's own reason, and that indistinguishability is the
manipulation being tested.
